## Goal

Give The Threshold real gating, so the La Finka digital garden can drop staticrypt and use The Threshold for per-page, per-group passwords. Every other consumer gets the same protection.

## What the garden does today

`digitalgarden_lafinka/scripts/gate.js` (plan: `_underScore/work/plans/active/260914-garden-page-gating.md`). After the 11ty build it encrypts each page whose note carries `garden-access: <group>`, using staticrypt with the password in `GARDEN_ACCESS_<GROUP>`. It fails closed: it reconciles the gated set against the committed `gated-urls.txt`, strips the surfaces `dg-hide` misses (graph.json, /~random/), and re-reads every file to prove the plaintext is gone. Its limits: images and PDFs stay public at their own URLs, and one page gets one password, so overlapping access needs a combined group.

## Shape (to settle in design)

- **Build side:** a Node CLI/library in this repo, `web-threshold seal`. It takes content plus a tier map (`tier → password`) and writes, per tier, a sealed blob: salt + IV + AES-GCM ciphertext, with the key derived by PBKDF2-SHA256 (WebCrypto-compatible).
- **Runtime side:** `<web-threshold>` gains a sealed mode. Instead of a `secrets` map it gets `sealed` blobs (inline, or via a URL). On submit it tries the typed phrase against each tier. A successful AES-GCM decrypt is the match, and it emits `tier-unlocked` with `{ tier, content }`. A wrong phrase still fails silently. No password or plaintext ever ships.
- **One page, many tiers:** a page can carry several sealed blobs, which removes the garden's "one password per page" limit.
- **Files:** optionally seal binary files (PDFs, images) as blobs decrypted to object URLs, which closes the "files stay public" gap for small files.
- **Fail-closed checks move with it:** the reconcile list and the plaintext-gone proof become part of `seal`, so every consumer inherits them.
- **v0.2 mode stays:** plain `secrets` remains for atmosphere-only gates (noesis).
