## 1. Owner requirements (261102)

> "password guessing is fine, maybe they will find a hit. I would like to have several passwords per page to allow for easter eggs."

> "We want to build this to facilitate multiple uses."

> "phrases also will unlock portions of a website. THink of threshold as the entry point to a labyrinth - depending upon what you enter different things could be allowed, could re-reoute you to another page etc... It should be designed in a way that is rather dynamic to facilitate playful experimentation later."

> "Session Storage per tab, also curious if we are building this in a way that easily allows adding or removing them? I imagine some kind of config and mapping?"

**Uses:** hidden text/HTML, hidden files, whole gated pages, site reactions, portions of a site, re-routing. **Decided:** eggs first, on this repo's demo; the garden stays on staticrypt for now; `seal` is generic; weak phrases warn and are never refused; wrong phrases are silent by default, with an opt-in message.

**Config and mapping.** The doors file (§ 7) is the config and the mapping, separate from the public `threshold.config.ts`. Adding, changing or removing a door is one entry plus a rebuild. Removal only affects new builds: there is no revocation. A fresh salt per build means any rebuild makes open sessions retype. There is no runtime door editing.

| Constraint (Threshold project page [read]) | Result |

| Plain mode | Unchanged for any page without `sealed`. The plain entry gains only a protected submit hook and the `sealed` refusal (f LOW). |

## 3. Threat model

Sealing hides content from anyone reading public output until they hold a phrase. Guessing is offline and unthrottled, which the owner accepts for eggs. It does not defend against a holder sharing a phrase, a compromised host, or a third-party script on the page (either captures the phrase). There is no revocation. Not for PII, financials or anything regulated (`web-access-control-patterns.md`).

## 4. The unlock record and format

### Bundle

Versioned JSON, base64url fields. An unknown `v` is refused; `v` covers cipher and KDF algorithm (e-4). An unknown or missing `kdf.norm` is also refused with `threshold-error`, so a future fold can't read as a silently wrong phrase (e-7). Other unknown fields are ignored.

```json
{
  "v": 1,
  "kdf": { "iter": 600000, "salt": "<16 bytes>", "norm": "fold1" },
  "slots": [ { "iv": "<12 bytes>", "ct": "<AES-256-GCM(KEK, padded record)>" } ],
  "inline": [ { "pid": "<random>", "iv": "<12 bytes>", "ct": "<AES-256-GCM(CEK, bytes)>" } ]
}
```

**No AAD, no bundle `id` (e-4).** Only the host can swap ciphertext, and a host can already capture phrases (§ 3). A swapped payload fails the tag anyway, because keys are random per payload.

### The record: what a slot decrypts to

```json
{
  "tier": "fox",
  "open": {
    "note": { "k": "<CEK>", "type": "text/html", "pid": "<inline id>" },
    "map":  { "k": "<CEK>", "type": "image/png", "iv": "<12 bytes>", "src": "/s/9f2c….sealed" }
  },
  "data": { "route": "/s/x7f3a…/", "theme": "moss", "sound": "bell", "step": 3 }
}
```

- **`tier`** is a name, passed out as today's `detail.tier`.
- **`open`** maps site-chosen names to keys. An inline entry has `pid`. A URL entry has `src` and its `iv`, so the `.sealed` file is pure ciphertext (e-13). URL-loaded payloads have no public index.
- **`data`** is any JSON, passed out untouched, with no schema and no reserved keys. A site inventing `sound` or `step` needs no release and no format change.

**What stays hidden (e-12).** `data` values stay out of public output. Handler code, CSS class names and asset names are public, so a hidden effect needs its assets sealed through `open`.

Records are padded to a 256-byte multiple; slots are shuffled; content keys are random per payload.

The site does everything visible. `seal`'s **shell** for a whole gated page is an ordinary consumer: inline element plus a handler that replaces the document.

```ts
interface TierUnlockedDetail {
  tier: TierName;
  data?: unknown;                        // sealed mode, untouched
  names?: string[];                      // keys of open
  open?(name: string): Promise<Blob>;    // inline or URL; lazy; Blob.type from the record
  replayed?: boolean;                    // came from session memory, not typing
}
```

`<web-threshold sealed="#wt-bundle">` reads an inline JSON script; `sealed="/s/site.json"` fetches a same-origin URL (cross-origin is refused).

**Modes never fall back.** Once sealed, `secrets` is never consulted; setting both emits `threshold-error` and refuses; a failed load never falls through to plain mode.

**The sealed entry (e-11, f-6, f-7).**
- A single file, `dist/web-threshold-sealed.js`, since an inlined shell's relative dynamic import 404s. Built by its own `vite.sealed.config.ts`, one entry, `emptyOutDir: false`, as a separate build step like the CLI.
- A superset of plain, reached through a protected submit hook in `web-threshold.ts`, because `#onSubmit` and `#input` are private [read].
- If plain registers first, `sealed` emits `threshold-error` and refuses submits. Plain-entry faults emit after an await (f LOW). The demo imports only the sealed entry.
- `sideEffects` gains the sealed file and `exports["./sealed"]` has `types`; otherwise a bare import is dropped and the element never registers.

**`detail` is visible to every script on the page**, so sealed pages carry no third-party scripts. `seal` warns on an external `<script src>` in any file containing `<web-threshold sealed`, and the README says to self-host (e-11).

### Phrase matching: `fold1` (e-14)

NFD → remove combining marks → NFC → curly quotes to straight → `–` `—` to `-` → `…` to `...` → collapse whitespace → trim → `toLowerCase()` (not locale-dependent). One shared function for `seal`, the scan and the element, with a test vector in the golden bundle. iOS smart punctuation is why dashes and ellipsis fold [unverified on a device].

**Accents are ignored (owner, 261102) [ran]:** `σας`, `σάς`, `ΣΑΣ` and `Σάς` open the same door, and `cafe` opens `café`. A typed `σασ` does not match. Phrases differing only by accent, such as `ano` and `año`, are duplicates and abort.

### KDF and many phrases

**One derivation per attempt, then trial decrypts.** On an M4 Max in Node 24.22, 1,000 wrong-key trials take 14 ms against 41 ms for one 600k derivation [ran]. The derivation drives latency, not the slots.

**Iterations: a constant, 600,000 (f-8)**, OWASP's PBKDF2-HMAC-SHA256 figure [read; undated, addressing server password storage]. Real-phone latency is **not measured**; my estimate is 100–800 ms [unverified]. Over 1 s on the phone test returns to the owner. The element refuses above 5,000,000.

**Phone route (e-10).** `crypto.subtle` is undefined on a plain http LAN URL, so the bench page reaches the phone through an HTTPS tunnel, or a preview of that page only.

**Slot limits (e-13):** warn above 256, abort above 1,024. The example record costs about 737 bytes per slot [ran: computed], so 256 slots is about 190 KB and 1,000 about 740 KB. Array length publicly shows the door count.

### Shared salt with weak eggs beside a strong phrase

**One salt per `seal` run.** Per-slot salt means N derivations per attempt, which many eggs rule out.

- **What sharing costs.** One guess tests every slot at one derivation, so a dictionary run finds all weak eggs together. Against a strong phrase, sharing removes a factor of N: log2(N) bits, 6 at N=64.
- **A cracked egg exposes** that egg's phrase, `tier`, `data`, and the payloads and URLs in its own record, plus the author's style, so a strong phrase should be random words. **It does not expose** any other phrase, slot or payload: content keys appear only in records that declare them.

`seal` aborts if two doors fold to the same phrase, since they would share a KEK. IVs are random 96-bit.

### Wrong phrase stays silent; faults do not

All slots failing their tag is the only "wrong phrase" signal: no event, no text, input cleared at once. Opt-in `report-wrong` emits `tier-rejected` with no payload; the site decides what to show.

- **Pending loads (e-8).** A submit awaits a pending load. Empty input after folding skips derivation. A failed load emits `threshold-error`, never `tier-rejected`.
- **Faults.** Malformed bundle, unsupported `v` or `norm`, failed fetch or missing `crypto.subtle` emit `threshold-error` with `{ code }` plus `console.error`, and show the visitor nothing.
- **Busy.** The element reflects `aria-busy` and `busy` during derivation and drops further submits, since a slow phone's gap looks like failure.

### Files

**Text** is a MIME list: `text/html`, `text/plain`, `text/css`, `text/markdown`, `application/json`, `image/svg+xml` (f-9), inline up to 64 KiB. Anything else is binary, URL-loaded at a random path. AES-GCM in WebCrypto is one-shot, so both copies sit in phone memory: warn above 2 MiB, abort above 10 MiB per file. Phone behaviour at those sizes and iOS PDF from `blob:` are [unverified].

## 5. Re-routing and portions of a site

### Re-routing

A route is `data.route`, and the site's handler calls `location.assign`. **The handler skips routing when `replayed` is true (e-9).** Otherwise a reload at the route's source loops.

**What a static host cannot hide:** a URL that exists can be fetched, and any blob it serves is public. A random path is unguessable, not protected. A sealed page (random path plus `seal` shell) is protected by its phrase, not its path. Without `remember`, the target shows its own door.

### Bundle scope (e-2)

One `seal` run writes **one site bundle at `s/site.json`, plus inline copies in shells**. A record can name any payload, so a phrase on one page opens content on others. A site can ignore a phrase by place, using `data`.

### Session memory (e-1)

**Opt-in `remember="session"`, off by default.**

- **Stored:** each KEK that opened a slot, as raw base64 in a `sessionStorage` array, de-duplicated by value. It lasts across pages and reloads in that tab and ends when the tab closes. A plain new tab starts fresh; a tab opened from this one may inherit a copy [unverified].
- **Readable by page scripts, accepted.** Such a script captures the phrase anyway (§ 3). A KEK opens its own slot only and never reveals the phrase.
- **Replay.** On load, the element tries stored KEKs and emits `tier-unlocked` with `replayed: true`, so sites have one code path.
- **Late listeners (e-9).** Replay starts after an await. Attach listeners before connecting the element, in the import's task, or on `document`. Later listeners miss replays; there is no re-emit.
- **Stale keys.** After a rebuild, old KEKs stop matching and stay inert. Storage failure degrades to retyping, not a fault.

## 6. Deferred and out

**Deferred by the owner, 261102 (f-1, f-10):** chains and decoys. Neither needs a format change to add later, and a site can fake a chain in its own handler with free-form `data`, with nothing enforcing the order.

**Out:** per-page scope, per-bundle salts, game state, counters, timers, hints, AND-doors, per-visitor state, server checks, token URLs, any route or effect vocabulary, hosted builds (e-3).

## 7. `seal` and the slices

### CLI

`src/seal/`, added as a subcommand in `src/cli/run.ts`; the `web-threshold` bin already exists (e-4). `src/seal/` joins `src/cli` in the main tsconfig's `exclude` and in `tsconfig.cli.json`'s `include` [read]; `fold1` and the format types live in `src/gate/`, free of node imports (f LOW).

```
web-threshold seal --doors doors.json --out dist [--shell shell.html] [--public-fixture]
```

```json
{
  "payloads": { "note": { "from": "private/note.html", "type": "text/html" },
                "vault": { "from": "private/vault.html", "type": "text/html", "page": "s/x7f3a…/index.html" } },
  "doors": [ { "tier": "fox", "phrase": "the fox was here", "open": ["note"], "data": { "theme": "moss" } },
             { "tier": "keeper", "phrase": "another phrase", "open": ["vault"], "data": { "route": "/s/x7f3a…/" } } ],
  "allowPublic": ["/about/"]
}
```

**The doors file is a secret.** Phrases never go in argv. **A doors file or `from` tracked by git aborts; `--public-fixture` is the exception for the demo. With git absent, the summary says "not checked" (e-3).** A hosted build needs an answer later; this note does not design it.

**Order, exit non-zero on any fault:** validate → seal in memory → read back → scan `--out` plus the bundle's bytes → write (e-15, g-7). Weak means under 14 characters, a warning heuristic by `tier`, never printing the phrase or its length.

| Guard | Rule |
|---|---|
| Doors file | Inside `--out` (symlinks resolved), missing or unparseable aborts; a public copy aborts by hash (g-2). Unknown payload name, empty or duplicate phrase after folding abort. |
| `from` | A source inside `--out` aborts. |
| Read-back and isolation | Each door's phrase must open **exactly** its declared names, byte-identical. No record holds an undeclared key; no two payloads share a key. A random wrong phrase opens nothing. |
| Scan | The one rule below. |
| File classes (e-6) | Every public file is text (`.map` included), compressed (`.gz`, `.br`, decompressed then scanned) or known binary, with counts in the summary. An unknown extension aborts. |
| Binary | A file hashing the same as a sealed `from` aborts, checked only at a matching size, so large media is never read (g-5). Derived images are out of scope. |
| Rerun and limits | `--out` already holding `s/site.json`, or § 4's limits, abort. |

**The scan: one rule (f-2, f-3, f-4, f-5).** Across every public file, check each target against the text both unstripped and with tags stripped, each also with escapes decoded (`\n \r \t`, `\uXXXX`, `%XX`, entities) (g-1), after `fold1`. Each file is checked and dropped, so memory stays one file at a time (g-5). The element's own bytes aren't exempt until the shell ships in slice 2 (g proportion); a phrase colliding with its text uses `allowPublic`. Tokens are `[\p{L}\p{N}]+` runs. **A hit of 3+ tokens or 16+ characters aborts. A shorter hit warns, by `tier`, with exit 0.** `allowPublic` is the one exact-match carve-out, for phrases, `data` and payloads, printed in the summary (g-10). A target with no tokens (emoji, symbols), or in a script written without spaces, also matches as folded text (g-9).

**Targets:** each phrase, each `data` string, each `page` path and its directory form, and each text payload as 8-token runs (the whole text if shorter). Runs keep ordinary three-word overlaps from aborting every build.

**Stated plainly:** a short route such as `/x/` is one token and only warns; a long random route aborts [ran: token counts]. Other encodings, such as base64, aren't read. Graphs, feeds and search indexes are the site's to strip.

## 10. Tests that must exist

Each guard needs a planted fault it catches and a known-good input it passes (`memory/feedback/guards-fail-closed.md`). Canaries are nonsense tokens. Tests write only to temp directories.

- **Config and mapping:** add a door, change a door and remove a door, each as one entry plus a rebuild. The new phrase opens; the removed phrase is silent against the new build.
- **Scan, asserting exit codes (f-5):**
  - **Abort, exit non-zero:** a 3+ token canary planted in body text, `meta content`, `alt`, `href` and an inline script; split across tags; in a `.gz`, a `.br` and a `.map`; Greek planted as `ΣΑΣ ΜΑΣ ΖΑΡΙ` against a target `σάς μας ζάρι`; curly quotes against a straight-quoted target; a single 16+ character token; a long `page` path in directory form.
  - **Warn, exit 0:** a 1–2 token phrase under 16 characters; a route `/x/`.
  - **Silent, printed in summary:** the same target listed in `allowPublic`. 
  - Also: an unknown extension aborts; phrases are absent from logs and errors.
- **Wrong phrase silent:** no `tier-unlocked`, no `threshold-error`, no `tier-rejected` unless opted in and then without the phrase; no DOM change except `busy` and `aria-busy` set and removed (f LOW); input cleared. `constructor`, `__proto__`, `toString` silent in both modes. Double submit makes one attempt. Empty input skips derivation. A wrong phrase never enters session memory.
- **Faults:** malformed bundle, unknown `v`, unknown or missing `norm`, iterations over ceiling, cross-origin URL, failed fetch (including a submit during it), missing `crypto.subtle`, `sealed` under the plain entry, including plain registered first: each emits `threshold-error` without unlocking and never `tier-rejected`.
- **Record and isolation:** `data` deep-equal, including odd shapes. With N doors, each phrase opens exactly its declared names.
- **Fold:** golden vectors for curly quotes, dashes, `…`, whitespace, `σας`/`σάς`/`ΣΑΣ`, `cafe`/`café`; duplicates after folding abort, including accent-only ones.
- **Session memory, in happy-dom:** off by default writes nothing. Stored once per value. A new salt stops matches without a fault. Storage failure degrades silently. `replayed` true only on replay. A listener attached in the import's task receives replays.
- **Each guard fails on broken input** (one test per § 7 row), including tracked doors with and without `--public-fixture`, `seal` stubbed to write plaintext, and a record with an undeclared key. Slice 1 refuses each f-9 input. A weak phrase warns and **succeeds**, printing neither phrase nor length.
- **Demo handler:** a cross-origin route doesn't navigate; a `data` value containing markup stays text.
- **Mutation:** `knowledge/tools/mutation-check.py`, no-op first; removing each guard must fail a named test.
- **Compatibility:** modes differ; both set refuses; plain-mode tests pass against both entries; noesis builds. A consumer-build test keeps a bare `./sealed` import registered (f-7). A v1 golden bundle, with fold vector, decrypts in Node, WebKit, Chromium and Firefox.
- **Real use:** phone latency at 600k and 64+ slots recorded here; demo screenshots via `knowledge/tools/ui-smoke.py --device both`, reviewed.
